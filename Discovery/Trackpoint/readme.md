# U75 — Trackpad Controller

*PC110 Motherboard · KiCad reverse-engineering project (Open-Source-PC110)*

---

## 1. Summary

**U75** is the **trackpad (pointing-device) controller** on the IBM PC110 motherboard. Instead of a dedicated touch ASIC, the design uses a small general-purpose **4-bit microcontroller** running firmware that scans the capacitive/resistive pad matrix, reads the physical click buttons, and reports pointer movement to the host over a PS/2-style clock + data interface.

| Field | Value |
|---|---|
| Reference designator | **U75** |
| Part number (Value) | **D17137AGT** (NEC µPD17137A) |
| Device class | 4-bit single-chip microcontroller (NEC "17K" / µPD17134A subseries) |
| Footprint | **PC110:SSOP-28** (28-pin shrink small-outline package) |
| Schematic description | "Trackpad Controller" |
| Net-naming prefix | `D171_` (derived from the part number) |
| Source document | `Mainboard.pdf` — *PC110 Motherboard*, generated by KiCad Eeschema |

## 2. The part: NEC µPD17137A

`D17137AGT` decodes to NEC's **µPD17137A**, a member of the **µPD17134A subseries** of NEC's **17K-family 4-bit single-chip microcontrollers** (circa early 1990s). The leading `D` is NEC's standard prefix (µPD), and the `GT` suffix denotes the package option.

Key characteristics of the family:

- 4-bit CMOS single-chip microcontroller architecture.
- On-chip ROM/RAM, timer, and general-purpose I/O ports organized into nibble-wide ports (P0A, P0B, P0C, P1A, P1B …).
- Designed for low-cost embedded control tasks — exactly the role it plays here, scanning a pointing-device sensor and emulating a mouse.

Using a programmable MCU (rather than fixed-function silicon) is why the schematic exposes raw port lines (`P0A0`, `P0B1`, etc.) directly to the pad — the scanning logic lives in firmware.

## 3. Connections / net map

All I/O nets carry the `D171_` prefix (after the part number). Grouped by function:

### Pad sensing matrix (scan / sense lines)
These read finger position off the trackpad surface.

- **Port 0A:** `/D171_P0A0`, `/D171_P0A1`, `/D171_P0A2`, `/D171_P0A3`
- **Port 0B:** `/D171_P0B0`, `/D171_P0B1`, `/D171_P0B2`, `/D171_P0B3`
- **Port 0C:** `/D171_P0C2`, `/D171_P0C3`
- **Port 1A:** `/D171_P1A0`, `/D171_P1A1`, `/D171_P1A2`, `/D171_P1A3`
- **Port 1B:** `P1B0` (appears as the auto-named net `Net-(U75-P1B0)`)

### Button inputs
- `/TRKPD_Lclick` — left physical click button
- `/TRKPD_Rclick` — right physical click button

### Host interface (pointer data out)
- `/D171_GPCLK` — PS/2-style clock line
- `/D171_GPDATA` — PS/2-style data line

### Control
- `Net-(U75-INT)` — interrupt line

### Power
- **`PNET3`** — supply rail
- **`GND`** — ground

U75 sits in a dense region of the motherboard alongside the core system controllers, and the CPU data bus (`/CPU_D28`–`/CPU_D31`) routes nearby.

## 6. Functional picture

```
                 +-------------------------+
  Pad matrix --->|  P0A0..P0A3             |
  (rows/cols)    |  P0B0..P0B3             |
                 |  P0C2, P0C3             |
                 |  P1A0..P1A3, P1B0       |
                 |                         |
  L/R buttons -->|  TRKPD_Lclick           |---> GPCLK  (PS/2 clock) --> host KBC
                 |  TRKPD_Rclick           |---> GPDATA (PS/2 data)  --> host KBC
                 |                         |
                 |  U75  (NEC uPD17137A)   |---> INT (interrupt)
                 |  SSOP-28, 4-bit MCU     |
                 +-----------+-------------+
                       PNET3 |  | GND
                             |  |
                        decoupling: C87, C126, C135
```

The MCU continuously drives/reads the port lines to scan the pad, debounces the two click inputs, and streams the resulting pointer packets to the system's keyboard/mouse controller over the `GPCLK`/`GPDATA` pair.
